# Levia

Тихий дневник практики отпускания эмоций. В основе — техника отпускания Лестера Левенсона: каждая сессия проходит пять шагов — назвать ситуацию, найти чувство, увидеть корневое «хочу», пройти четыре внутренних вопроса и заметить, что изменилось.

Levia — независимое приложение, не связанное с Sedona Training Associates. «Sedona Method» — их зарегистрированная марка; в интерфейсе название метода упоминается только в разделе «О приложении».

PWA, локально-first. Все данные хранятся в IndexedDB на устройстве пользователя — без авторизации, аккаунтов и облачной синхронизации. Интерфейс на трёх языках: English (по умолчанию), русский, українська.

## Стек

- Next.js 14 (App Router) · TypeScript strict · Tailwind CSS
- Dexie + dexie-react-hooks (IndexedDB)
- Собственная i18n: типизированные словари + React-контекст + Intl
- Native `<dialog>` + собственный service worker, без `next-pwa`

## Скрипты

```bash
npm run dev          # дев-сервер с hot reload
npm run build        # production-сборка
npm run start        # запустить production-сборку
npm test             # unit-тесты (vitest + fake-indexeddb)
npm run e2e          # сборка + сквозные сценарии в Chromium
npm run i18n:table   # таблица EN | RU | UK для вычитки переводов
npm run icons        # перегенерировать PWA-иконки (sharp)
```

## Деплой

Vercel, нулевой конфиг: `npm run build` запускается автоматически, тесты в сборку не встроены.

Страницы рендерятся на сервере на каждый запрос (ƒ в выводе сборки): сервер читает язык из cookie или `Accept-Language` и сразу отдаёт HTML на нужном языке. Поэтому нужен хостинг с Node-рантаймом Next.js — чисто статический экспорт не подойдёт. Нужен и HTTPS: без него service worker не зарегистрируется, а Android не предложит установить PWA.

## Локализация (i18n)

### Как это устроено

- **Выбор языка:** cookie `levia-locale` (пишется только при ручном выборе в настройках) → самый приоритетный язык браузера (`ru*` → ru, `uk*` → uk) → en. Логика — `lib/i18n/config.ts`.
- **Без мерцания:** корневой layout определяет язык на сервере (`lib/i18n/server.ts`), ставит `<html lang>` и `<title>` и передаёт язык в `LocaleProvider`. Первый HTML уже на нужном языке.
- **Мгновенная смена:** `LocaleProvider` (`lib/i18n/LocaleProvider.tsx`) держит язык в state; переключатель в настройках меняет state, cookie, `<html lang>` и заголовок вкладки без запроса к серверу. При загрузке провайдер сверяется с cookie — на случай, если service worker отдал из кэша HTML, отрендеренный до смены языка.
- **Форматирование:** `lib/i18n/format.ts` — склонения через `Intl.PluralRules`, даты через `Intl.DateTimeFormat` и `Intl.RelativeTimeFormat`. Для EN регион берётся из браузера (en-US → 12-часовое время), иначе en-GB.
- **Словари:** `lib/i18n/dictionaries/{en,ru,uk}.ts`. `en.ts` задаёт структуру; `ru.ts` и `uk.ts` объявлены через `satisfies Dictionary`, поэтому пропущенный, лишний или опечатанный ключ — ошибка `tsc` с точной строкой.

### Как добавить строку

1. Добавь ключ в `lib/i18n/dictionaries/en.ts` в нужный раздел.
2. `npx tsc --noEmit` покажет, где его не хватает в `ru.ts` и `uk.ts`, — добавь переводы.
3. В компоненте: `const { t } = useI18n();` → `{t.section.key}`.
   - Подстановки: строка `"Step {current} of {total}"` → `fmt(t.session.stepOf, { current, total })`.
   - Числа: значение `{ one, few, many, other }` (в en — `{ one, other }`, в ru/uk `other` — запасная форма для дробей, ставим форму few) → `plural(t.home.daysUnit, n)`. Если в формах есть `{count}`, он подставится сам.
   - Перенос строки — `\n` в тексте и `whitespace-pre-line` у элемента.
4. Не пиши текст прямо в `app/` и `components/`: тест `no-hardcoded-text` падает на любой кириллице вне комментариев.
5. `npm test`, затем `npm run i18n:table > table.md` — таблица для вычитки.

Правило по марке: название «Sedona Method / метод Седоны / метод Седони» допустимо только в `settings.aboutText`, рядом с пометкой о независимости. Это проверяет `i18n.test.ts`.

### Как добавить язык

1. `lib/i18n/config.ts`: код в `LOCALES`, самоназвание в `LOCALE_NAMES`, сопоставление тега браузера в `localeFromTag`.
2. `lib/i18n/dictionaries/xx.ts`: копия `ru.ts` или `uk.ts` с `satisfies Dictionary`, все строки переведены. Формы чисел — по категориям `new Intl.PluralRules("xx")` (`resolvedOptions().pluralCategories`).
3. `lib/i18n/dictionaries/index.ts`: добавь словарь в `dictionaries`.
4. Тесты: большая часть идёт по `LOCALES` и подхватит язык сама; проверку форм чисел, дословность четырёх вопросов и правило по марке дополни вручную.
5. `public/manifest.webmanifest` и `public/offline.html` остаются на английском — они общие для всех языков.

## Данные и миграции

- База — `PauseDB` (Dexie). Номер версии схемы только растёт: v1 — исходная, v2 — чувства хранятся кодами (`anxiety`, `anger`, …) вместо русских слов. Миграция v1 → v2 идёт в одной транзакции при первом открытии новой версии приложения.
- Старые русские значения переводятся в коды через `normalizeFeeling()` в `lib/feelings.ts`. Её же использует импорт, поэтому старые бэкапы импортируются корректно. Нераспознанное значение не теряется: становится `other`, а исходный текст уходит в `customFeeling`.
- Бэкап (`lib/backup.ts`): `{ version, exportedAt, sessionCount, sessions }`. Экспорт пишет `version: 2`; импорт принимает v1, v2 и сырой массив, дубли отсеивает по `createdAt`.
- **Откат кода после миграции — только в крайнем случае.** Старая версия откроет обновлённую базу (Dexie 4 это допускает), но покажет коды вместо слов («anxiety» вместо «тревога»). Сессии, созданные во время отката, запишутся русскими словами; миграция второй раз не запустится, однако новая версия всё равно покажет их правильно — `feelingLabel()` нормализует значение при выводе. Проблемы лучше чинить новым деплоем; перед деплоем, меняющим схему, — свежий экспорт.

## Тесты

- `npm test` — unit-тесты: нормализация чувств, миграция настоящей базы v1 на фикстуре (`lib/__tests__/fixtures/backup-v1.json`), импорт/экспорт, определение языка, полнота словарей, склонения и даты, отсутствие захардкоженного текста, файлы PWA.
- `npm run e2e` — собирает проект, поднимает `next start` и проходит сценарии в Chromium: отсутствие мерцания языка, импорт старого бэкапа, смена языка без перезагрузки, полная сессия, удаление, экспорт и повторный импорт, форматы дат в EN, оффлайн-режим и кэш service worker. Каждый сценарий — в чистом профиле браузера; твои данные не затрагиваются.
  - Браузер один раз: `npx playwright-core install chromium`. Или свой: `CHROMIUM_PATH=/path/to/chrome npm run e2e`.
  - Против задеплоенной версии: `E2E_BASE_URL=https://… node scripts/e2e.mjs`. Оффлайн-сценарий в этом режиме пропускается — он останавливает локальный сервер, чтобы честно отключить сеть.

## Структура

```
app/                 — страницы App Router
components/          — UI-примитивы и шаги сессии
lib/                 — Dexie-схема, чувства, бэкап, константы
lib/i18n/            — языки, словари, провайдер, форматтеры
lib/__tests__/       — unit-тесты и фикстура старого бэкапа
public/              — manifest, sw.js, иконки, offline.html
scripts/             — генератор иконок, таблица переводов, e2e
```

## Внутренние имена

`PauseDB` (имя Dexie-базы), префикс `pause-` у кэша service worker (сейчас `pause-v2`) и `pause:toast` (ключ sessionStorage) — наследие первоначального названия проекта. Сохранены намеренно: переименование базы привело бы к потере данных у пользователей, остальные ключи держим стабильными заодно. Номер кэша поднимаем, когда меняется закэшированная оболочка (manifest, offline.html).
